# 记忆协议（完整细节）

配合 `SKILL.md`。定义存储格式、读写协议、升分与墓碑规则。设计参考：Memory Bank（结构化文件 + 读写协议）、语义记忆（结构化事实）、Zep/审计型记忆（时效 + 出处 + 可回溯）。

## INDEX.md 模板

只做索引与定位，**不放知识正文、不放分数**，控制在百行内。

```markdown
# 记忆索引
> 使用协议（对 AI）：写业务代码前，任务命中下方关键词/目录 → 读对应领域文件。
> 分数行为：1=推断（先问再用；数值类照写+插 TODO 注释）；2=可用；3~4=放心用；5=冲突以它为准。
> 更新领域知识时按本 skill 的写入协议执行（升分 / 墓碑 / 冲突仲裁）。

## 系统定位
{一句话：这个系统做什么、服务谁}

## 上下游地图
{对接哪些外部系统，各一句话}

## 全局术语索引
| 术语 | 所在文件 |
|------|----------|

## 领域文件清单
- 订单.md — 关键词：关单/退款/超时/预售 | 目录：src/order/**
- 结算.md — 关键词：对账/分账/提现 | 目录：src/settle/**
```

领域清单每行带**业务关键词 + 顶层目录 glob**（只到顶层目录粒度，如 `src/order/**`，避免重构后索引腐烂；不写具体符号名）。

## 领域文件与条目格式

条目是打分、检索、引用的原子单位。每条有**永不复用的稳定 ID**：`{域前缀-序号}`，如 `{#ORD-007}`。改标题不改 ID；删条目 ID 作废不回收；墓碑与索引一律引用 ID。

```markdown
---
domain: 订单
prefix: ORD
nextId: 8
---
# 订单域

## 术语
### 预售单 {#ORD-001} [3分 | 对话 | 2026-07-08 | src/order/presale.ts]
定义：先付定金、到期付尾款的订单。
不是什么：不是"预占单"（type=3）；预售单不占实时库存。

## 规则
### 超时未支付自动关单 {#ORD-005} [4分 | 对话 | 2026-07-20]
下单后 30 分钟未支付 → 自动关单并释放库存。
边界：预售单尾款期不受此 30 分钟限制。
```

条目头 `[分数 | 出处 | 日期 | 可选代码位置]`：
- **出处**：`对话` / `文档` / `代码` / `用户确认`。
- **日期**：最近一次更新日。
- **代码位置**：可选，指向相关锚点，便于核验（不是从代码抄，是给人回查）。

## 写入协议

1. **判定该不该收**：过收录红线 + 信息差测试；不过则不写。
2. **定域与 ID**：归入对应 `domains/<域>.md`，取 `nextId` 作为新 ID，然后 `nextId +1`。
3. **定分**：按可信度表打分；用户明确陈述给 3–4，随口提及给 2，AI 推断给 1。
4. **写条目**：标题 + ID + 头信息 + 定义/规则正文；能写"不是什么"就写（划清边界最防错）。
5. **更新索引**：新域或新术语时，同步 INDEX 的清单/术语表。

## 升分与墓碑（自我修正）

- **升分**：同一事实被用户**再次确认**或在实践中验证 → 分数 +1（上限 5），更新日期。
- **冲突/纠正**：用户否定或给出新说法 → **新建条目**记录正确版本，**旧条目落墓碑**：

```markdown
### ~~旧规则标题~~ {#ORD-005} [已废弃 | 2026-07-25]
superseded-by: {#ORD-011}
原内容保留一行，说明为何废弃（防止同样的错误再次被"学"回来）。
```

- 墓碑**不删除、不回收 ID**，只标记；检索时忽略，但保留可回溯性（审计）。

## 读取协议

1. 任务开始，读 `INDEX.md`。
2. 任务描述命中某行的关键词或落在其目录 glob 内 → 读对应领域文件。
3. 命中的条目：1 分先问、数值类先问；其余按分使用。
4. 若发现代码现实与记忆冲突 → 提示用户并按"冲突/纠正"流程更新。

## 边界与纪律

- 只存业务语义，不存代码可推导事实，不存聊天原文。
- 知识进 git（随项目走），团队共享同一份记忆。
- 不确定的不臆造为高分；宁可标 1 分先问。
