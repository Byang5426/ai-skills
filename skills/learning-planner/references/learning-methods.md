# 学习方法论（应用指南）

配合 `SKILL.md`。这些是设计学习方案时的依据与用法，均为业界公认方法。

## Dreyfus 技能获取五阶段 —— 用来定"阶段骨架"

| 阶段 | 特征 | 学习方案侧重 |
|------|------|--------------|
| 1 新手 | 只会照规则做，脱离情境 | 明确步骤、最小可跑示例、快速成就感 |
| 2 进阶新手 | 能识别部分情境线索 | 多样例子、开始处理变体 |
| 3 胜任 | 能定计划、取舍、独立完成任务 | 真实项目、排错、权衡决策 |
| 4 精通 | 凭经验整体把握、直觉判断 | 复杂场景、性能/边界、阅读源码 |
| 5 专家 | 直觉流畅、能创新 | 深水区、贡献/设计、教别人 |

用法：先问清目标停在哪个阶段，只排到该阶段（多数人到 3「胜任」就够用）。

## 刻意练习（Deliberate Practice，Ericsson）—— 用来设计"练习"

有效练习 = **明确目标 + 专注 + 即时反馈 + 略超当前能力**。不是"多做就行"。
每个练习条目要写清：练什么、怎样算达标、如何获得反馈（测试/输出对照/自评）。

## 20 小时法则（Josh Kaufman）—— 用来"拆解 + 快速起步"

1. **解构**技能为子技能，抓最影响结果的部分先练。
2. 学"足够多以能**自我纠错**"，别一开始追求完备。
3. **移除练习障碍**（环境、工具先备好）。
4. 前 ~20 小时集中、连续地练，快速跨过"笨拙期"。

用法：第 2 步拆解 + 第一阶段"快速起步"就用它。

## Bloom 认知层级 —— 用来写"可检验的阶段目标 + 自检"

记忆 → 理解 → 应用 → 分析 → 评估 → 创造。
低阶段用低层动词（记忆/理解），高阶段用高层（分析/评估/创造）。
每个目标用一个动词写成可检验句：如"能**应用** `EXPLAIN` 优化一条慢查询"、"能**评估**两种索引方案的取舍"。自检题对应该动词。

## 项目驱动学习 —— 用来配"每阶段产出"

建真实东西比看教程留存高得多。每阶段至少一个动手产出（小到一段脚本，大到一个应用），让知识落到"做得出来"。

## 间隔复习（Spaced Repetition）—— 用来保证"留存"

新知识按扩大的间隔复习（如次日、3 天、1 周、1 月）。方案里安排轻量回顾点，或用 Anki 等；避免"学完即忘"。

## 代码库上手法 —— 用于"学一个项目"

综合社区经验（跑起来 + 任务驱动 + 小步交付）：

1. **先跑起来**：把项目 run/测试跑通，动手戳一戳看反应。
2. **追一条主链路**：选一个典型请求/功能，端到端读它经过的文件（用通用的自顶向下/自底向上分析法）。
3. **任务驱动**：接一个小任务/小 bug，"为了做它"去学相关区域，而不是通读全库。
4. **小步交付**：尽快提交一个能 ship 的小改动，正反馈 + 熟悉流程。
5. **借力**：有人能带就 pair / 走查；没有就让 AI 讲解关键路径。

用法：学项目时，把上面 5 步映射成阶段（跑通→读主链路→接小任务→独立改动→能设计新功能），阶段目标同样用 Bloom 动词写。
