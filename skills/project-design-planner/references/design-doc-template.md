# 设计方案模板

配合 `SKILL.md` 第 3 步。结构综合自 Google Design Doc、三层洋葱结构、RFC 与 ADR。**按需裁剪**：小需求只用前几节给"思路概述"，别硬套全部。

## 完整设计文档模板

```markdown
# <项目/特性> 设计方案

## 1. 背景与范围 (Context & Scope)
简述系统所处环境与本次要做的事（客观事实，非需求）。附系统上下文图。

## 2. 目标与非目标 (Goals / Non-Goals)
- 目标：本次设计要达成的（可衡量）
- 非目标：本可作为目标、但明确不做的（如"本期不做多租户"）

## 3. 需求 (Requirements)
- 功能性需求：系统对外要做什么
- 非功能性需求：性能、可用性、安全、可维护、成本等

## 4. 设计方案 (The Design)
先总览，后细节：
- 总体架构（配 C4 / mermaid 图）
- 关键接口（只写与设计相关的，别照抄完整定义）
- 数据存储与模型（同上，聚焦相关部分）
- 关键流程/时序（mermaid 时序或流程图）

## 5. 备选方案与取舍 (Alternatives & Trade-offs)
| 方案 | 优点 | 缺点/代价 | 是否采用 |
|------|------|-----------|----------|
| 方案 A（选中） | ... | ... | ✅ |
| 方案 B | ... | ... | ❌ 原因 |

## 6. 横切关注点 (Cross-cutting)
安全、隐私、可观测性（日志/指标/追踪）、性能、兼容性——各写"如何影响 + 如何应对"。

## 7. 里程碑 / 落地步骤 (Milestones / Rollout)
分阶段推进计划、灰度/回滚策略、依赖项。

## 8. 风险与未决问题 (Risks / Open Questions)
已知风险 + 需要评审拍板的问题。
```

## ADR 模板（记录单个关键决策）

```markdown
# ADR-NNN: <决策标题>
- Status: Proposed / Accepted / Superseded
## Context
面临的问题、约束与背景事实。
## Decision
我们决定采用什么。
## Consequences
带来的正面收益与负面代价/后续影响。
```

## 轻量版（"思路概述"骨架）

需求较小时，用这个精简结构即可：

```markdown
# <特性> 设计思路
- 背景/问题：...
- 目标：...
- 方案概述：...（配一张示意图）
- 关键取舍：...（为什么这么选，放弃了什么）
- 落地步骤：1) ... 2) ...
- 风险/待确认：...
```

## 图示建议（mermaid）

- 系统上下文图 / C4 Container 图：`graph TD` 表达系统与外部/容器关系。
- 关键流程：`sequenceDiagram` 或 `flowchart`。
- 节点 ID 用 camelCase/下划线，标签含特殊字符时用双引号包裹。
