# 测试设计原则（详解）

配合 `SKILL.md`。均为业界公认实践。

## 测试金字塔

- **单元测试**（最多）：快、隔离、覆盖逻辑分支。
- **集成测试**（适量）：验证模块/服务间协作。
- **端到端 E2E**（最少）：贵、慢、脆，只覆盖关键用户旅程。
- 反过来的"冰淇淋筒"（E2E 多、单元少）会又慢又脆，避免。

## AAA（Arrange-Act-Assert）

每个测试分三段，结构清晰：

```
// Arrange 准备输入与依赖
// Act    执行被测行为（只一次）
// Assert 断言结果
```

- **一个测试一个 Act**：一次只验证一个行为；多种输入用参数化测试，别把多个 Act 塞一个测试。
- **最小可通过**：断言写到刚好能验证行为，别过度。

## FIRST 原则

- **Fast**：毫秒级，慢测试没人愿意频繁跑。
- **Isolated**：测试之间互不依赖、不依赖执行顺序、不共享可变状态。
- **Repeatable**：任何环境/任意次运行结果一致（不依赖时间、时区、随机、网络）。
- **Self-validating**：自动判定通过/失败，不靠人看输出。
- **Timely**：及时写（TDD 里先于实现）。

## 测行为，不测实现细节

- 断言"对外可观察的行为/输出/契约"，不是"内部怎么实现的"。
- 判据：**在不改变行为的前提下重构，测试应保持绿**。若一重构就红，说明测到了实现细节。
- 好处：测试成为重构的安全网，而不是重构的阻力。

## 覆盖 unhappy path

正常路径之外，重点覆盖：

- 边界值（0 / 空 / 最大 / 越界）
- 错误与异常（非法输入、依赖失败、超时）
- 并发/竞态（如相关）
- 权限/鉴权失败

## Mock / 测试替身（test doubles）——何时用

- **用**：外部副作用（网络、时钟、随机、文件系统、第三方 API）——为了 Isolated / Repeatable。
- **少用/别用**：你自己的纯逻辑、领域对象——直接用真实对象更能测到真实行为。
- 经验法则：**非得大量 mock 才能测 → 先怀疑设计耦合过紧**，而不是继续加 mock。
- 优先用真实对象或轻量假实现（fake），其次 stub，最后才 mock 交互。
